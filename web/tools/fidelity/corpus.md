# 保真度评测语料与流程（M2）

目标：证明「输出与原稿肉眼难辨」。结构自检只能证明包是自洽的，证明不了观感，所以这一关必须看图。

## 语料清单（M2 gate：前 6 类各 1 个 deck，其余进 backlog）

| # | 类别 | 关注点 | 判定 |
|---|---|---|---|
| 1 | 纯文字（中英混排） | 换行、字距、溢出 | 核心类，必须「一致或轻微可接受」 |
| 2 | 图文混排 | 图片清晰度、位置 | 核心类 |
| 3 | 表格 | 边框/底色/列宽 | 核心类 |
| 4 | 图表（柱/饼/折线） | echarts 异步绘制是否截到半成品 | 核心类 |
| 5 | 大字报 / 标题页 | 大字号边缘锯齿 | 核心类 |
| 6 | 复杂母版 / 页眉页脚 | 母版元素是否齐全 | 核心类 |
| 7 | SmartArt | 已知限制候选 | 允许标注为已知限制 |
| 8 | 艺术字 / 文本效果 | 已知限制候选 | 允许标注为已知限制 |
| 9 | 公式 | 已知限制候选 | 允许标注为已知限制 |
| 10 | WPS 导出的 pptx | 方言 OOXML 兼容性 | 允许标注为已知限制 |

每个 deck 记录：来源、页数、体积、所用字体、是否有备注。

## 流程

1. 在应用里转换（默认「均衡」档），记录耗时/体积/结构自检结果（必须 PASS）。
2. 解出输出的背景图：
   `cd web && node tools/fidelity/extract-output.mjs <converted.pptx> out/<deck>/app`
3. 生成参考渲染（需要 LibreOffice + poppler）：
   `cd web && ./tools/fidelity/render-reference.sh <deck.pptx> out/<deck>/ref`
4. 逐页并排比对 `app/out-NN.jpg` 与 `ref/ref-NN.png`，按上表判定并截图留证。
5. **真值复核**：参考渲染只是可复现的一致参考系（LibreOffice 排版 ≠ PowerPoint）。
   核心 6 类还需在 PowerPoint 或 WPS 中打开原稿与输出各看一遍；当前开发机（Arch Linux）没有
   PowerPoint，这一步需要在有 Office/WPS 的机器上做。
6. 换一台字体环境不同的机器重复 1–4（客户端字体不可控是头号保真度风险，见计划书 §14-1）。

## 记录格式

`out/<deck>/report.md`：每类一行 —— 类别 / 页数 / 判定（一致 | 轻微可接受 | 明显差异）/ 差异描述 / 截图路径。
